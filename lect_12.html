Додаємо меню в Main() — CRUD не переписуємо

Тимчасовий робочий варіант: меню в Main(), але операції з книгами виконуються тільки через наявний сервіс.

BookCatalog catalog = new BookCatalog();
while (true)
{
    Console.WriteLine("1 — Додати, 2 — Показати, 0 — Вихід");
    string? command = Console.ReadLine();
    if (command == "0") break;

    if (command == "1")
    {
        Console.Write("Назва: ");
        string title = Console.ReadLine() ?? "";
        Console.Write("Автор: ");
        string author = Console.ReadLine() ?? "";
        Book? book = catalog.Create(title, author);
        Console.WriteLine(book is null ? "Помилка даних." : $"Додано: {book}");
    }
    if (command == "2")
        foreach (Book book in catalog.ReadAll())
            Console.WriteLine(book);
}

На відміну від моноліту з лабораторної №20, цей код не містить List<Book> чи алгоритмів CRUD у Main().

Що саме потрібно відокремити?

Після лекції 11 BookCatalog уже виконує CRUD. Для додавання багаторазового консольного меню студент розмістив у Main() цикл, Console.ReadLine() та повідомлення. Яке вдосконалення найдоречніше?

A. Перенести List<Book> з BookCatalog у Main().

B. Винести меню та введення в ConsoleView, залишивши CRUD у BookCatalog.

C. Реалізувати всі CRUD-методи повторно в ConsoleView.

D. Перенести Console.ReadLine() всередину BookCatalog.

Правильна відповідь: B.

  • A — хибно: повертає сховище до точки запуску та руйнує вже створену межу Service.
  • B — правильно: нова відповідальність — UI; сервіс уже реалізовано.
  • C — хибно: дублює алгоритми й створює два незалежні місця зміни правил CRUD.
  • D — хибно: прив’язує Service до консолі замість відокремлення інтерфейсу.

Single Responsibility Principle (SRP)

Принцип єдиної відповідальності

Клас має представляти одну узгоджену сферу поведінки й мати одну основну причину для змін.

Одна відповідальність

Керування каталогом книг.

Різні відповідальності

Керування каталогом і форматування консольного меню.

SRP — один із принципів SOLID, а не вимога «один метод на клас».

BookCatalog уже відповідає SRP

Одна узгоджена сфера

П'ять методів — не п’ять обов’язків

Клас BookCatalog містить методи Delete() і PrintMenu(). Яка зміна найкраще відповідає SRP?

Хто має обробляти введене Id?

Користувач увів текст "abc" замість номера книги. Яка частина застосунку повинна обробити невдале перетворення рядка на число?

Book.cs: звіряємо код із лекцією 11

Це наявний клас із лекції 11. Перевіряємо його архітектурну роль, а не реалізуємо заново.

public class Book
{
    public int Id { get; }
    public string Title { get; }
    public string Author { get; }

    public Book(int id, string title, string author)
    {
        if (id <= 0)
            throw new ArgumentOutOfRangeException(nameof(id));
        if (string.IsNullOrWhiteSpace(title) ||
            string.IsNullOrWhiteSpace(author))
            throw new ArgumentException("Назва й автор обов'язкові.");
        Id = id;
        Title = title.Trim();
        Author = author.Trim();
    }

    public override string ToString() => $"{Id} | {Title} | {Author}";
}

Показано компактний еквівалент моделі; у власному проєкті студенти використовують готовий Book.cs без повторного створення.

private static int? ReadId()
{

    return null;
}
