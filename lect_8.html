1. Проблема статичних масивів

  • Масиви надзвичайно швидкі та ефективні (безперервний блок пам'яті).
  • Головний недолік: жорстке обмеження фіксованого розміру.

// Виділяємо пам'ять рівно під 3 елементи. Не більше!
string[] students = new string[3];

Для додавання 4-го елемента доведеться створювати новий масив, копіювати туди всі дані та переприсвоювати посилання.

2. Еволюція: Проблема ArrayList

Раніше використовували ArrayList. Він міг змінювати розмір, але зберігав дані як System.Object. 


ArrayList list = new ArrayList();
list.Add(3);            // Пакування (Boxing): int перетворюється на Object
list.Add("Hello");      // Рядок також стає Object

int sum = 0;
foreach (int x in list) 
{
    sum += x; // АВАРІЯ! InvalidCastException (Рядок не стане числом)
}

Наслідки: відсутність безпеки типів, падіння швидкодії через постійне пакування та розпакування (Boxing/Unboxing).

Рішення: Узагальнення (Generics)

List<T> — це сучасний строго типізований список.
Літера <T> означає Type parameter (параметр типу).


// Строга типізація: приймає ТІЛЬКИ цілі числа
List<int> numbers = new List<int>();
numbers.Add(10); 
// numbers.Add("Hello"); // Помилка компіляції! Безпека типів у дії.

// Ініціалізатор колекції
List<string> cities = new List<string> { "Київ", "Львів" };

// Дістаємо елемент без жодного приведення типів
string capital = cities[0];

3. Анатомія List<T>: Count та Capacity

  • Count — фактична кількість елементів у списку.
  • Capacity — фізичний розмір внутрішнього масиву (місткість).

List<int> numbers = new List<int>();
// Count: 0, Capacity: 0

numbers.Add(1);
// Count: 1, Capacity: 4

numbers.Add(2); numbers.Add(3); numbers.Add(4);
// Count: 4, Capacity: 4 (масив заповнений повністю)

numbers.Add(5); // Переповнення!
// Count: 5, Capacity: 8 (місткість ПОДВОЇЛАСЯ: 4 * 2)

Як працює автоматичне розширення

  1. Список створює новий внутрішній масив вдвічі більшого розміру.
  2. Усі існуючі елементи швидко копіюються зі старого масиву в новий.
  3. Старий масив відкидається (знищується збирачем сміття).
  4. Новий елемент додається у першу вільну комірку.

Порада щодо оптимізації:

Використовуйте new List<int>(1000), якщо заздалегідь знаєте кількість елементів, щоб уникнути постійного подвоєння масиву та копіювання даних.

4. Базові операції керування даними


List<string> planets = new List<string> { "Венера", "Марс" };

// ДОДАВАННЯ ТА ВСТАВКА
planets.Add("Юпітер");       // В кінець
planets.Insert(0, "Меркурій"); // На конкретну позицію

// ПОШУК
bool hasEarth = planets.Contains("Земля"); // Результат: false
int marsIndex = planets.IndexOf("Марс");   // Результат: 2

// ВИДАЛЕННЯ
planets.Remove("Венера"); // Видалення за значенням (всі наступні зсуваються вліво)
planets.RemoveAt(0);      // Видалення за конкретним індексом
planets.Clear();          // Очистити весь список (Count стане 0)

5. Ітератор foreach: Безпечний обхід

Спеціальний цикл для перебору колекцій від початку до кінця без необхідності управління індексами. 


List<string> languages = new List<string> { "C#", "Java", "Python" };

foreach (string lang in languages) 
{
    Console.WriteLine($"Мова програмування: {lang}");
}

На відміну від циклу for, він повністю унеможливлює помилку виходу за межі масиву (IndexOutOfRangeException) і робить код чистішим.

Критичне правило безпеки foreach

Категорично заборонено змінювати структуру колекції (додавати або видаляти елементи) безпосередньо під час її обходу циклом foreach.


List<int> numbers = new List<int> { 1, 2, 3, 4, 5 };

foreach (int num in numbers) {
    if (num % 2 == 0) {
        numbers.Remove(num); // ПОМИЛКА! InvalidOperationException
    }
}

Для видалення елементів за умовою всередині циклу використовуйте звичайний for із зворотним відліком (від кінця до початку).

6. Архітектура: Списки у зв'язках класів (HAS-A)

Реалізація відношення «один-до-багатьох» з дотриманням інкапсуляції.


class Department {
    public string Name { get; set; }
    
    // Інкапсульований список! Зовнішній код не може зробити Clear()
    private List<Teacher> teachers = new List<Teacher>();

    public Department(string name) { Name = name; }

    // Доступ надається виключно через безпечні методи
    public void AddTeacher(Teacher t) {
        if (t != null) teachers.Add(t);
    }

    public void RemoveTeacher(Teacher t) {
        teachers.Remove(t);
    }
}

7. Підсумки

  • List<T> знімає обмеження фіксованого розміру статичних масивів.
  • Узагальнення (Generics, <T>) гарантують безпеку типів на етапі компіляції та рятують від InvalidCastException.
  • Відсутність Boxing/Unboxing значно економить пам'ять та час процесора.
  • Властивість Count — це реальні дані, а Capacity — зарезервована внутрішнім масивом пам'ять.
  • Не модифікуйте колекцію всередині foreach.
  • Завжди ховайте списки під модифікатор private в архітектурі ваших класів.
