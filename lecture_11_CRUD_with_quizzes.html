Що зберігає ідентичність сутності?

Ситуація: у каталозі зберігаються дві книги з однаковою назвою, але з Id = 3 та Id = 7. Назву книги № 3 змінено.

Яке твердження правильне?

  1. У каталозі тепер одна сутність, бо назви збігаються.
  2. Зміна назви створює нову сутність з іншим Id.
  3. Книга № 3 залишається тією самою сутністю.
  4. Ідентичність книги визначає її індекс у списку.

Завдання: назвіть літеру відповіді та поясніть різницю між Id й атрибутом Title.

Правильна відповідь: C. Ідентичність визначається стабільним Id; Title — змінний атрибут. Книга № 3 після зміни назви залишається тією самою сутністю.

  • A — хибне: однакові назви не роблять дві книги однією сутністю.
  • B — хибне: зміна назви — це оновлення атрибута, а не створення нової сутності.
  • C — правильне: змінюється лише Title, а Id лишається тим самим.
  • D — хибне: індекс у списку може змінюватися після видалень або вставок і не є надійним ідентифікатором.

Інваріанти протягом життєвого циклу

01. Унікальна ідентичність.

У межах каталогу кожна книга має власний додатний Id.

02. Коректні атрибути.

Title та Author не складаються тільки з пробілів.

03. Стабільний Id.

Редагування не змінює ідентифікатор сутності.

04. Передбачувана невдача.

Некоректна операція не повинна частково змінити дані.

Перевірка інваріантів

Вимога: навіть якщо операція завершилася невдало, каталог має залишитися коректним.

Оберіть ДВА правильні твердження

  1. Після невдалої операції Create лічильник _nextId можна збільшити.
  2. Кожний доданий запис повинен мати додатний унікальний Id.
  3. Після невдалого Update допустима часткова зміна назви.
  4. Якщо нова назва складається з пробілів, Update має відхилити зміну.

Правильні відповіді: B і D. Невдала операція не повинна змінювати стан каталогу, а всі успішно додані записи мають зберігати інваріанти.

  • A — хибне: якщо Create завершився невдало, не можна «витрачати» наступний Id.
  • B — правильне: кожен доданий запис повинен мати додатний унікальний Id.
  • C — хибне: після невдалого Update часткові зміни неприпустимі.
  • D — правильне: назва з одних пробілів є некоректною, тому Update має відхилити зміну.

Які дії змінюють дані?

Read

Лише отримання даних.

  • Не змінює каталог.
  • Не створює дублікатів.
  • Може повернути null.

Create · Update · Delete

Змінюють вміст або стан каталогу.

  • Створення нового запису.
  • Зміна атрибутів.
  • Видалення запису.

Визначте операції, що змінюють дані

Після створення двох книг студент виконав чотири дії. Які виклики змінюють стан каталогу?

A. catalog.Read(1)

B. catalog.ReadAll()

C. catalog.Update(1, "Нова", "Автор")

D. catalog.Delete(2)

Умова: обидві книги існують, а нові атрибути коректні. Виберіть усі виклики, що змінюють дані, і поясніть, чому інші їх не змінюють.

Правильні відповіді: C і D. Лише ці виклики змінюють стан каталогу.

  • A — хибне: Read(1) лише повертає книгу, але не змінює дані.
  • B — хибне: ReadAll() надає доступ до перегляду колекції без її модифікації.
  • C — правильне: Update(...) змінює атрибути наявної книги.
  • D — правильне: Delete(2) вилучає книгу з каталогу.

Модель Book: атрибути та конструктор

Властивості мають лише get; зовнішній код не може довільно змінювати Id, Title або Author.

public class Book
{
    public int Id { get; }
    public string Title { get; }
    public string Author { get; }

    public Book(int id, string title, string author)
    {
        // Перевірки значень — на наступному слайді
        Id = id;
        Title = title.Trim();
        Author = author.Trim();
    }
}

Зверніть увагу: це схема структури моделі; повний конструктор містить валідацію.

Book: перевірка інваріантів

У повній реалізації конструктор перевіряє аргументи до присвоєння значень.

public Book(int id, string title, string author)
{
    if (id <= 0)
        throw new ArgumentOutOfRangeException(nameof(id));
    if (string.IsNullOrWhiteSpace(title))
        throw new ArgumentException("Назва не може бути порожньою.");
    if (string.IsNullOrWhiteSpace(author))
        throw new ArgumentException("Автор не може бути порожнім.");

    Id = id;
    Title = title.Trim();
    Author = author.Trim();
}

IsNullOrWhiteSpace перевіряє рядок, Trim() прибирає крайні пробіли, а throw сигналізує про помилку.

Create: створення нової книги

Метод перевіряє поля, створює книгу, додає її до списку та повертає створений об’єкт.

public Book? Create(string title, string author)
{
    if (string.IsNullOrWhiteSpace(title) ||
        string.IsNullOrWhiteSpace(author))
        return null;

    Book book = new Book(_nextId, title, author);
    _books.Add(book);
    _nextId++;
    return book;
}

Гарантія: _nextId збільшується лише після успішного додавання книги.

Знайдіть помилку в Create

У методі Create змінили порядок дій. Знайдіть логічну помилку.

public Book? Create(string title, string author)
{
    int id = _nextId++;
    if (string.IsNullOrWhiteSpace(title) ||
        string.IsNullOrWhiteSpace(author))
        return null;

    Book book = new Book(id, title, author);
    _books.Add(book);
    return book;
}

Виклики: спочатку Create(" ", "Автор"), потім Create("Алгоритми", "Автор"). Який Id отримає друга книга? Як усунути помилку?

Відповідь: друга книга отримає Id = 2, тому що _nextId++ виконано до перевірки даних, навіть якщо створення не відбулося.

Виправлення: спочатку перевірити вхідні дані, а _nextId++ виконати тільки після успішного _books.Add(book).

Типова помилка: здаватися, що невдала операція «нічого не робить». Насправді вона може непомітно зіпсувати стан лічильника.

Read і ReadAll: пошук та перегляд

Пошук за Id використовує LINQ; для перегляду колекції повертається інтерфейс лише для читання.

public Book? Read(int id)
{
    return _books.FirstOrDefault(book => book.Id == id);
}

public IReadOnlyList<Book> ReadAll()
{
    return _books.AsReadOnly();
}

FirstOrDefault повертає перший збіг або null, якщо книгу не знайдено.

Прогнозуйте результат ReadAll

Метод ReadAll() повертає _books.AsReadOnly(). Розгляньте послідовність дій:

BookCatalog catalog = new BookCatalog();
var view = catalog.ReadAll();

catalog.Create("Алгоритми", "Автор");
Console.WriteLine(view.Count);

Що буде виведено на екран?

A. 0    B. 1    C. Помилка компіляції    D. null

Поясніть, чи створює AsReadOnly() незалежну копію списку.

Правильна відповідь: B — 1. AsReadOnly() повертає обгортку над наявним списком, а не його копію. Тому через view видно подальші зміни колекції.

Контрольний сценарій CRUD

Простежте стан BookCatalog після шести викликів. Новий каталог порожній, наступний Id — 1.

var a = catalog.Create("A", "Автор");
var b = catalog.Create("  ", "Автор");
var c = catalog.Create("C", "Автор");
var d = catalog.Delete(1);
var e = catalog.Delete(1);
var f = catalog.Read(2);

Запишіть: a?.Id, b is null, c?.Id, d, e і f?.Title. Скільки книг залишиться?

Відповідь: a?.Id = 1; b is null = true; c?.Id = 2; d = true; e = false; f?.Title = "C"; кількість книг — 1.

Причини: неуспішний Create не займає Id; успішний Delete(1) прибирає лише книгу № 1; повторне видалення повертає false.

На що часто не зважають: після видалення книги № 1 книга № 2 продовжує існувати, тому Read(2) повертає книгу "C".
