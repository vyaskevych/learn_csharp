Життєвий цикл сутності

Життєвий цикл описує появу, доступність, зміну й вилучення сутності зі сховища.

Є в каталозіRead — перегляд, Update — зміна

Інваріанти протягом життєвого циклу

01. Унікальна ідентичність.

У межах каталогу кожна книга має власний додатний Id.

02. Коректні атрибути.

Title та Author не складаються тільки з пробілів.

03. Стабільний Id.

Редагування не змінює ідентифікатор сутності.

04. Передбачувана невдача.

Некоректна операція не повинна частково змінити дані.

C

Додати нову книгу з новим Id.

R
Read — читання

Знайти книгу або переглянути весь каталог.

U

Змінити назву/автора, зберігши Id.

D

Лише отримання даних.

Модель Book: атрибути та конструктор

Властивості мають лише get; зовнішній код не може довільно змінювати Id, Title або Author.

public class Book
{
    public int Id { get; }
    public string Title { get; }
    public string Author { get; }

    public Book(int id, string title, string author)
    {
        // Перевірки значень — на наступному слайді
        Id = id;
        Title = title.Trim();
        Author = author.Trim();
    }
}

Зверніть увагу: це схема структури моделі; повний конструктор містить валідацію.

Book: перевірка інваріантів

У повній реалізації конструктор перевіряє аргументи до присвоєння значень.

public Book(int id, string title, string author)
{
    if (id <= 0)
        throw new ArgumentOutOfRangeException(nameof(id));
    if (string.IsNullOrWhiteSpace(title))
        throw new ArgumentException("Назва не може бути порожньою.");
    if (string.IsNullOrWhiteSpace(author))
        throw new ArgumentException("Автор не може бути порожнім.");

    Id = id;
    Title = title.Trim();
    Author = author.Trim();
}

IsNullOrWhiteSpace перевіряє рядок, Trim() прибирає крайні пробіли, а throw сигналізує про помилку.

Create: створення нової книги

Метод перевіряє поля, створює книгу, додає її до списку та повертає створений об’єкт.

public Book? Create(string title, string author)
{
    if (string.IsNullOrWhiteSpace(title) ||
        string.IsNullOrWhiteSpace(author))
        return null;

    Book book = new Book(_nextId, title, author);
    _books.Add(book);
    _nextId++;
    return book;
}

Гарантія: _nextId збільшується лише після успішного додавання книги.

Read і ReadAll: пошук та перегляд

Пошук за Id використовує LINQ; для перегляду колекції повертається інтерфейс лише для читання.

public Book? Read(int id)
{
    return _books.FirstOrDefault(book => book.Id == id);
}

public IReadOnlyList<Book> ReadAll()
{
    return _books.AsReadOnly();
}

FirstOrDefault повертає перший збіг або null, якщо книгу не знайдено.

Update: зміна атрибутів

Спочатку перевіряємо нові значення, потім шукаємо позицію книги за Id.

public bool Update(int id, string newTitle, string newAuthor)
{
    if (string.IsNullOrWhiteSpace(newTitle) ||
        string.IsNullOrWhiteSpace(newAuthor))
        return false;

    int index = _books.FindIndex(book => book.Id == id);
    if (index == -1)
        return false;

    _books[index] = new Book(id, newTitle, newAuthor);
    return true;
}

Змінюються атрибути; ідентифікатор книги зберігається.

Delete: вилучення за Id

Спочатку шукаємо позицію за ідентифікатором; лише потім вилучаємо знайдений елемент.

public bool Delete(int id)
{
    int index = _books.FindIndex(book => book.Id == id);
    if (index == -1)
        return false;

    _books.RemoveAt(index);
    return true;
}

Delete(2) → true, якщо запис знайдено.

Повторний Delete(2) → false.

Важливо перевірити як успішні, так і невдалі операції.

СитуаціяВикликОчікувано
ОновленняUpdate(1, "Нова назва", "Автор")true; Id сталий
Некоректне оновленняUpdate(1, " ", "Автор")false; стара назва
ВидаленняDelete(1), Read(1)true; потім null
Повторне видаленняDelete(1) вдругеfalse

У кожному тесті переконайтеся, що невдала операція не пошкодила дані.

Складність операцій для List<T>

Нехай n — кількість записів у каталозі.

ОпераціяТипова складністьПричина
CreateАмортизовано O(1)Додавання в кінець списку
Read(id)O(n)Лінійний пошук
Update(id)O(n)Пошук і заміна
Delete(id)O(n)Пошук та можливий зсув
ПеребірO(n)Відвідуємо всі записи

Для невеликого навчального каталогу цього достатньо; вибір іншого сховища залежить від характеру доступу до даних.

Практичне завдання

Розширте консольний приклад і перевірте поведінку каталогу після таких дій:

1. Некоректне оновлення

Спробуйте присвоїти порожню назву й перевірте незмінність початкових даних.

2. Пошук відсутнього Id

Спрогнозуйте результат Read(999).

3. Новий запис після видалення

Створіть книгу після Delete і порівняйте ідентифікатори.

Послідовність: прогноз → запуск → порівняння результату → пояснення, які інваріанти збережено.
