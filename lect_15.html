Етап 1. Метод синхронізації RefreshList()

Окремий допоміжний метод заповнює ListBox виключно з _catalog.ReadAll():

private void RefreshList()
{
    lstBooks.Items.Clear();

    foreach (Book book in _catalog.ReadAll())
    {
        lstBooks.Items.Add(book);
    }

    btnUpdate.Enabled = false;
    btnDelete.Enabled = false;
}

Зауважте: ReadAll() повертає IReadOnlyList<Book>, тому форма може перебирати книги через foreach, але не змінювати колекцію сервісу.

Чому в ListBox зберігаємо об’єкти Book?

Зберігаємо об’єкт Book

  • lstBooks.Items.Add(book);
  • WinForms викликає Book.ToString() → 1 | Алгоритми | Олена Коваль.
  • Через SelectedItem одразу маємо selected.Id, selected.Title, selected.Author.

Якщо зберігати лише рядки

  • lstBooks.Items.Add(book.ToString());
  • SelectedItem буде типом string, а не Book.
  • Для Update чи Delete довелося б розбирати текст, щоб дістати Id.

Згадайте Лекцію 11 (слайд 17): перевизначений Book.ToString() автоматично працює і в консолі, і в ListBox!

Етап 2. Пошук за Id: btnFind_Click

Прямий графічний аналог ReadId() + _catalog.Read(id) із Лекції 12:

private void btnFind_Click(object? sender, EventArgs e)
{
    if (!int.TryParse(txtSearchId.Text.Trim(), out int id) || id <= 0)
    {
        lblStatus.Text = "[Помилка формату UI] Введіть додатне ціле число Id.";
        return;
    }

    Book? found = _catalog.Read(id);
    if (found is null)
    {
        lblStatus.Text = $"[Service] Книгу з Id = {id} не знайдено.";
        return;
    }

    lstBooks.SelectedItem = found;
    lblStatus.Text = $"Знайдено: {found}";
}

Що станеться, якщо UpdateButtonsState() лишити всередині if?

У lstBooks_SelectedIndexChanged розробник поставив UpdateButtonsState() усередину гілки if (lstBooks.SelectedItem is Book selected). Після видалення книги Items.Clear() скидає вибір. Якими залишаться кнопки Update і Delete?

Кнопки залишаться візуально активними (Enabled = true), хоча SelectedItem уже null. Оскільки гілка if не виконалася, виклик UpdateButtonsState() пропустився. Цей метод завжди викликаємо безумовно — поза if.

Підсумки лекції 15

Архітектура

Book і BookCatalog з Лекцій 11–12 працюють у Windows Forms без змін; MainForm замінив ConsoleView.

Синхронізація

BookCatalog — єдине джерело даних; після успішного CRUD викликаємо RefreshList() і ResetEditor().

Межа відповідальностей

UI обробляє події, TryParse, MessageBox і вивід; Service керує колекцією та бізнес-правилами.

Поза межами лекції: DataGridView, DataBinding, збереження даних у файлі чи БД та DI-контейнери.
